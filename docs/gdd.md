Here’s a **concise but complete 2D isometric Game Design Document** for a **Dungeon Keeper–style game**, with **Rust** as the implementation target. Think lava-lit ambition, cackling imps, and a codebase that refuses to segfault 🧱🔥

---

# Game Design Document

## Project Codename: **Deep Dominion**

### Genre

- God Game / Dungeon Management
- Real-time strategy
- Indirect control simulation

### Perspective

- 2D Isometric (tile-based)

### Target Platform

- Browser and PC (Windows, Linux)
- Touch-first controls with keyboard + mouse shortcuts

### Engine & Tech

- **Language:** Rust
- **Rendering:** Macroquad
- Explicit `GameState` and `EntityManager` ownership with focused Rust modules
- Deterministic simulation for replay/debugging
- Data-driven content via JSON / RON

---

## 1. Core Fantasy

> You are an unseen evil intelligence carving a dungeon beneath the world, tempting creatures with gold and comfort, defending your heart from foolish heroes who believe themselves brave.

The player never controls units directly in a tactical sense. Instead, they **shape space**, **set priorities**, and **exploit creature psychology**.

---

## 2. Core Gameplay Pillars

1. **Dig & Shape**
   - Carve rooms and tunnels from rock
   - Control dungeon flow and efficiency

2. **Creature Management**
   - Attract, house, feed, and discipline creatures
   - Balance happiness, greed, and fear

3. **Economy & Resources**
   - Gold, Mana, Territory, Threat
   - Spatial logistics matter

4. **Defense & Punishment**
   - Trap corridors
   - React to heroes and rival keepers

---

## 3. Camera & Presentation

### Camera

- Fixed isometric angle (approx 30–35°)
- Zoom in/out
- Edge scrolling or WASD pan

### Visual Style

- Chunky, readable sprites
- Strong silhouettes
- Exaggerated animations (idle, work, combat)
- Lighting used to communicate ownership and danger

---

## 4. World & Map Structure

### Tile Grid

- Square grid rendered isometrically
- Each tile has:
  - Terrain type
  - Ownership
  - Room association
  - Fog-of-war state

### Tile Types

- Solid Rock
- Earth
- Gold Vein
- Gems (infinite gold source)
- Reinforced Wall
- Claimed Floor
- Lava / Water (later)

---

## 5. Digging & Claiming

### Dig Orders

Player can:

- Mark tiles to dig
- Mark tiles to claim
- Mark walls to reinforce

**Imps** execute these tasks autonomously.

### Priority System

- Orders have priority levels
- Emergency orders override others
- Imps choose closest valid task

---

## 6. Rooms System

Rooms are defined by **contiguous claimed tiles of the same room type**.

### Core Rooms

| Room            | Purpose                           |
| --------------- | --------------------------------- |
| Lair            | Creature sleep & territory        |
| Hatchery        | Food generation                   |
| Treasury        | Gold storage                      |
| Training Room   | Creature leveling                 |
| Library         | Spell research                    |
| Workshop        | Traps & doors                     |
| Prison          | Capture heroes                    |
| Torture Chamber | Convert heroes / punish creatures |
| Dungeon Heart   | Core structure                    |

### Room Quality

- Size
- Shape (penalties for thin corridors)
- Room objects placed automatically

---

## 7. Creatures

### Creature AI Model

Each creature has:

- Needs (Sleep, Food, Gold, Training)
- Traits (Greedy, Lazy, Aggressive, Loyal)
- Mood (0–100)
- Current Task

Creatures **choose tasks**, the player only nudges.

### Example Creatures

| Creature | Role                |
| -------- | ------------------- |
| Imp      | Worker              |
| Goblin   | Weak fighter, cheap |
| Troll    | Workshop specialist |
| Warlock  | Research            |
| Demon    | High upkeep, strong |

### Desertion

- Low mood → refuses work
- Worse mood → leaves dungeon
- Extreme mood → attacks own dungeon

---

## 8. Player Interaction

### Hand of Evil

The player has a magical hand:

- Pick up and drop creatures
- Slap creatures (boost work, lower mood)
- Drop into rooms or danger

### Spells

- Cost mana
- Examples:
  - Speed
  - Heal
  - Possession (optional advanced feature)
  - Lightning (direct damage)

---

## 9. Economy

### Resources

**Gold**

- Mined, stored in treasury
- Used for rooms, creatures, traps

**Mana**

- Generated by dungeon size and rooms
- Used for spells

**Threat**

- Invisible value
- Higher threat attracts stronger heroes

---

## 10. Combat

### Combat Model

- Real-time
- Simple stats:
  - Health
  - Damage
  - Armor
  - Attack Speed

- Creatures auto-engage enemies in territory

### Heroes

- Spawn from map edges or portals
- Goal-based AI:
  - Steal gold
  - Kill creatures
  - Destroy dungeon heart

---

## 11. Traps & Doors

### Traps

- Triggered by enemies
- Limited charges
- Examples:
  - Spike Trap
  - Boulder Trap
  - Gas Trap

### Doors

- Slow enemies
- Require damage to break
- Can be locked magically

---

## 12. Progression

### Research Tree

Unlocked via Library:

- New rooms
- Traps
- Spells
- Creature types

### Campaign Structure

- Mission-based maps
- Persistent unlocks between missions
- Optional sandbox mode

---

## 13. Failure & Victory

### Lose Conditions

- Dungeon Heart destroyed

### Win Conditions

- Destroy all heroes
- Complete mission objective
- Survive X time

---

## 14. Technical Architecture (Rust)

### Simulation architecture

- Explicit state-owned systems:
  - AI Decision
  - Pathfinding
  - Room Validation
  - Economy Tick
  - Combat Resolution

### Pathfinding

- A\* on tile grid
- Cached paths per room

### Simulation

- Fixed timestep (e.g. 10–20 ticks/sec)
- Deterministic for replay/debug

### Data-Driven Design

- Creatures, rooms, traps defined in data files
- Hot-reload for tuning

---

## 15. Scope Control (Important)

### MVP Features

- Digging
- 4 rooms
- 3 creature types
- Basic hero invasion
- One map

### Explicit Non-Goals (Initial)

- Full possession mode
- Advanced fluids
- Modding support

---

## 16. Why This Works

- Indirect control reduces micro
- Isometric 2D keeps art scope sane
- Rust's explicit state ownership supports large simulations
- Dungeon Keeper fantasy remains intact
